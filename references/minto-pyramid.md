# Minto Pyramid Principle

**When to use:** Decision-oriented presentations where the audience needs a clear recommendation and the reasoning behind it. Executive briefings, strategy proposals, funding asks, status updates to leadership.

**When NOT to use:** Conference talks, workshops, or peer presentations where entertainment and tension matter more than efficiency. Use the storytelling/Why-What-How framework for those.

## The structure

Lead with the answer. Support it with grouped arguments. Each argument is supported by data.

```
            [Thesis / Recommendation]
           /           |              \
    [Argument 1]  [Argument 2]  [Argument 3]
     /      \       /      \       /      \
  [Data]  [Data] [Data]  [Data] [Data]  [Data]
```

## Rules

1. **Top-down.** State your conclusion first, then explain why. The audience should never have to wait for the point.
2. **MECE grouping.** Arguments at the same level are Mutually Exclusive and Collectively Exhaustive — no overlaps, no gaps.
3. **"So what?" test.** Every piece of data must answer "so what?" by supporting the argument above it. If it doesn't, cut it.
4. **Group in 3s.** The brain holds 3-5 parallel items comfortably. Never more than 5 at one level.

## Applied to slides

- Slide 1 = your thesis (the answer/recommendation, stated upfront)
- Each section = one supporting argument (MECE with the others)
- Each slide within a section = one piece of evidence for that argument
- Close = restate the thesis + the ask

## Source

Barbara Minto, _The Pyramid Principle_ (McKinsey, 1967). Standard framework for structured communication at consulting firms and executive-facing teams.
